================================================================================
R10 PURGE POLICY (ENFORCEMENT)
================================================================================

Scheduled: Daily @ 03:00 UTC (APScheduler, non-blocking)

Rules (priority-ordered):

  1. TTL Expiration [Priority 100]
     Rule: DELETE FROM agent_memory WHERE expires_at <= NOW()
     Effect: Removes all entries past their 480-min TTL

  2. Low Rating + Age [Priority 90]
     Rule: DELETE FROM agent_memory
           WHERE user_rating < 2 AND created_at < NOW() - INTERVAL '7 days'
     Effect: Removes poor-quality entries older than 7 days

  3. Keep Recent [Priority 110]
     Rule: Always keep latest 1000 completions per agent
     Effect: Protects recent entries even if low rating

Memory Thresholds:
  - Soft limit: 80 MB/agent → Warning
  - Hard limit: 100 MB/agent → Force purge
  - Soft chunk limit: 5000 chunks → Warning
  - Hard chunk limit: 10000 chunks → Force purge

Alerts (Slack if enabled):
  - If bytes_freed > 10 GB
  - If rows_deleted > 10,000
  - If purge_duration > 5 minutes

Logging:
  ✓ agent_memory_purge_log (append-only, immutable)
  ✓ agent_memory_metrics (time-series)
  ✓ Grafana dashboard (real-time)

RISK MITIGATION
================================================================================

Risk 1: RLS blocking legitimate access
  → Mitigation: Verify app.current_agent_id set before query
              Use SET app.current_agent_id = 'manta-03-s1' at connection time

Risk 2: Purge deleting recent entries
  → Mitigation: "Keep recent" rule (priority 110) protects latest 1000 completions

Risk 3: Large purge causing slowdown
  → Mitigation: APScheduler runs async (non-blocking), off-peak (03:00 UTC)

Risk 4: Slack alerts flooding
  → Mitigation: Conservative threshold (> 10 GB or > 10k rows)

Risk 5: Embedding vectors lost in purge
  → Mitigation: Stored in agent_state (persistent), never auto-deleted
