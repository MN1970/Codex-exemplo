Sistema de Orchestração — KB Evolution

Automação de evolução contínua da Knowledge Base (RAG) de Manta Maestro. O sistema ingere projetos finalizados, extrai insights via agentes especializados, valida por consenso, atualiza o KB e oferece controle humano em pontos críticos.

Visão Geral

A Knowledge Base que alimenta os agentes verticais (Manta 03-S1..S10) precisa evoluir com novos projetos concluídos. O desafio:

  • Coletar dados de múltiplas fontes (SharePoint, Supabase, sistemas legados)
  • Extrair features/insights em paralelo (one worker per segment)
  • Validar com consenso de 2-de-3 agentes especializados
  • Atualizar RAG sem quebrar modelos em produção
  • Rollback automático se contradição detectada
  • Audit trail completo (timestamp + confiança + decisão)

Este orquestrador roda em cadência (diária/semanal) ou manual, com aprovação humana para mudanças normativas críticas.

Análise: Airflow vs n8n vs Temporal

Apache Airflow Recomendado
  • Infraestrutura: Rodá em Kubernetes (já em uso em Manta)
  • DAG-as-Code: Python puro, versionável no Git
  • Logging: Built-in para cada task, com Web UI
  • Escalabilidade: Workers paralelos, suporta 1000s de tasks
  • Segurança: RBAC, secrets em vault, audit log nativo
  • Integrações: Operadores para Lambda, Spark, K8s, SQL
  • Curva de aprendizado em DAGs complexos
  • Overhead de recursos (memory para scheduler)
n8n Visual, não-código
  • UI visual: Drag-and-drop, sem código Python
  • Rápido prototipagem: Deploy em minutos
  • 200+ integrações: Salesforce, Slack, etc.
  • Menos controle sobre lógica complexa
  • Dependência de UI para manutenção (não versionável como code)
  • Escalabilidade limitada em paralelismo pesado
  • Audit trail não é tão granular quanto Airflow
Temporal Durable execution
  • Durable execution: Retry/timeout automático com estado persistido
  • Workflow-as-code: TypeScript/Go, altamente flexível
  • Escalabilidade: Suporta workflows de meses
  • Curva de aprendizado: modelo mental diferente (activity/workflow)
  • Menos adotado em Brasil; comunidade menor
  • Melhor para workflows de longa duração, não tanto para jobs diários

Recomendação para Manta Maestro

Apache Airflow. Razões:

  • DAG-as-Code (Python) alinha com prática de agentes em Python
  • Web UI robusta para observabilidade (logs, SLA, retries)
  • RBAC + secrets vault = segurança para gate humano de aprovações
  • Já em infra K8s de Manta; reutiliza secrets/monitoring existente
  • Task logging granular permite audit trail para compliance

Fases da DAG

1

Ingest

Coleta projetos com status "Finalizado" de SharePoint + Supabase. Filtra por data (últimas 7 dias) e segmento. Detecta duplicatas (por projeto_id).

2

Extract (Paralelo)

Para cada projeto, dispara worker por segmento. Cada worker invoca agente especializado (ex: agente-saneamento para S8) com prompt de extração de features normativas, riscos, benchmarks. Output: structured JSON com confiança.

3

Validate (Consensus)

Coleta respostas dos 3 agentes para o mesmo projeto. Se 2+ concordam (confiança >= 0.75), passa. Se contraditório, escala. Output: validated_insights + confidence_score.

4

Gate Humano (Crítico)

Se mudança toca em lei, norma ABNT, ou ANEEL/ANTAQ → pausa. MN recebe Slack com diff. Aprova via /kb-approve <change_id> ou rejeita. Timeout: 24h (escala)

5

Update KB

Insere insights validados em rag_chunks (Supabase). Versionamento automático: nova coluna kb_version incrementada. Rollback point criado.

6

Test Models

Roda 10 prompts de regressão (ex: "Como estruturar uma ETA em saneamento?" vs benchmark respostas). Se divergência > 5%, rollback automático.

7

Audit Log

Registra: projeto_id, mudanças, confiança, agentes que validaram, timestamp, autor (system vs MN), status. Imutável para compliance.

Workflow Detalhado (Pseudo-Python Airflow)

# dags/kb_evolution_dag.py

from airflow import DAG
from airflow.operators.python import PythonOperator
from airflow.operators.bash import BashOperator
from airflow.utils.task_group import TaskGroup
from datetime import datetime, timedelta
import json

default_args = {
    'owner': 'manta-maestro',
    'retries': 2,
    'retry_delay': timedelta(minutes=5),
}

with DAG(
    'kb_evolution',
    default_args=default_args,
    schedule_interval='0 9 * * *',  # 09:00 UTC
    catchup=False,
) as dag:

    # Task 1: Ingest
    def ingest_projects(**context):
        """Coleta projetos finalizados das últimas 7 dias."""
        import supabase

        client = supabase.Client(SUPABASE_URL, SUPABASE_KEY)
        projects = client.table('projects').select(
            '*'
        ).eq(
            'status', 'Finalizado'
        ).gte(
            'completed_at',
            (datetime.now() - timedelta(days=7)).isoformat()
        ).execute()

        # Filtra duplicatas
        new_projects = [p for p in projects.data
                        if not p.get('kb_ingested')]

        context['task_instance'].xcom_push(
            key='projects',
            value=new_projects
        )

        return len(new_projects)

    t_ingest = PythonOperator(
        task_id='ingest_projects',
        python_callable=ingest_projects,
    )

    # Task 2: Extract (Paralelo)
    with TaskGroup('extract_features') as extract_tg:

        def extract_segment(segment_code: str, **context):
            """Invoca agente especializado para segmento."""
            projects = context['task_instance'].xcom_pull(
                task_ids='ingest_projects',
                key='projects'
            )

            results = []
            for proj in projects:
                if proj['segment'] != segment_code:
                    continue

                # Invoca agent (ex: agente-saneamento)
                agent = load_agent(f'agente-{segment_code}')
                insights = agent.extract_features(proj)

                results.append({
                    'project_id': proj['id'],
                    'segment': segment_code,
                    'insights': insights,
                    'confidence': insights.get('confidence', 0.5),
                    'timestamp': datetime.now().isoformat(),
                })

            return results

        # Cria worker por segmento
        segments = ['S1', 'S2', 'S4', 'S8', 'S9']
        for seg in segments:
            PythonOperator(
                task_id=f'extract_{seg}',
                python_callable=extract_segment,
                op_kwargs={'segment_code': seg},
            )

    # Task 3: Validate (Consensus)
    def validate_consensus(**context):
        """Verifica se 2/3 agentes concordam."""
        # Busca resultados de extract_*
        task_ids = [f'extract_features.extract_{seg}'
                    for seg in ['S1', 'S2', 'S4', 'S8', 'S9']]

        all_results = []
        for tid in task_ids:
            res = context['task_instance'].xcom_pull(task_ids=tid)
            all_results.extend(res)

        import difflib
        validated = []
        contradictions = []

        for project_id, group in group_by(all_results, 'project_id'):
            insights_list = [r['insights'] for r in group]

            # Consenso: 2+ iguais (ou 75%+ similar)
            match_count = sum(1 for i in range(len(insights_list)-1)
                            if similarity(insights_list[i],
                                          insights_list[i+1]) > 0.75)

            if match_count >= 1:  # 2+ agentes concordam
                validated.append({
                    'project_id': project_id,
                    'insights': insights_list[0],
                    'confidence': avg([r['confidence'] for r in group]),
                    'validators': [r['segment'] for r in group],
                })
            else:
                contradictions.append({
                    'project_id': project_id,
                    'insights': insights_list,
                    'reason': 'No consensus',
                })

        if contradictions:
            notify_slack(f'Contradictions detected: {contradictions}',
                        channel='#manta-alerts',
                        escalate_to='mneves')
            raise Exception('Consensus failed')

        context['task_instance'].xcom_push(
            key='validated',
            value=validated
        )

        return len(validated)

    t_validate = PythonOperator(
        task_id='validate_consensus',
        python_callable=validate_consensus,
    )

    # Task 4: Gate crítico (pausa se lei/norma)
    def check_critical_gate(**context):
        validated = context['task_instance'].xcom_pull(
            task_ids='validate_consensus',
            key='validated'
        )

        critical_keywords = [
            'lei', 'norma', 'aneel', 'antaq',
            'licitação', 'regulamento'
        ]

        critical_changes = []
        for item in validated:
            text = json.dumps(item['insights']).lower()
            if any(kw in text for kw in critical_keywords):
                critical_changes.append(item)

        if critical_changes:
            # Pausa via Airflow sensor
            change_id = hash_dict(critical_changes)
            notify_slack(
                f'Gate crítico: aprovar via /kb-approve {change_id}',
                channel='#manta-ops',
                escalate_to='mneves'
            )
            # Aguarda sensor...

        return critical_changes

    t_gate = PythonOperator(
        task_id='check_critical_gate',
        python_callable=check_critical_gate,
    )

    # Task 5: Update KB
    def update_kb(**context):
        validated = context['task_instance'].xcom_pull(
            task_ids='validate_consensus',
            key='validated'
        )

        import supabase
        client = supabase.Client(SUPABASE_URL, SUPABASE_KEY)

        # Incrementa versão KB
        current_version = client.table('kb_meta').select(
            'version'
        ).order('created_at', desc=True).limit(1).execute().data[0]

        new_version = current_version['version'] + 1

        # Insere insights em rag_chunks
        for item in validated:
            client.table('rag_chunks').insert({
                'project_id': item['project_id'],
                'content': json.dumps(item['insights']),
                'confidence': item['confidence'],
                'kb_version': new_version,
                'validators': json.dumps(item['validators']),
                'created_at': datetime.now().isoformat(),
            }).execute()

        return {'version': new_version, 'count': len(validated)}

    t_update = PythonOperator(
        task_id='update_kb',
        python_callable=update_kb,
    )

    # Task 6: Test Models (Regressão)
    t_test = BashOperator(
        task_id='test_models',
        bash_command='python /opt/manta/regression_tests.py --kb-version {{ ti.xcom_pull("update_kb")["version"] }}',
    )

    # Task 7: Rollback se falha
    def handle_test_failure(context):
        version = context['task_instance'].xcom_pull(
            task_ids='update_kb'
        )['version']

        import supabase
        client = supabase.Client(SUPABASE_URL, SUPABASE_KEY)

        # Reverte para versão anterior
        client.table('rag_chunks').update({
            'active': False
        }).eq('kb_version', version).execute()

        notify_slack(
            f'Rollback: KB v{version} falhou testes. Revertido.',
            channel='#manta-alerts',
            severity='critical'
        )

    # Task 8: Audit Log
    def audit_log(**context):
        import supabase
        client = supabase.Client(SUPABASE_URL, SUPABASE_KEY)

        validated = context['task_instance'].xcom_pull(
            task_ids='validate_consensus',
            key='validated'
        )

        for item in validated:
            client.table('kb_audit').insert({
                'project_id': item['project_id'],
                'action': 'INSERT',
                'confidence': item['confidence'],
                'validators': json.dumps(item['validators']),
                'author': 'system',
                'timestamp': datetime.now().isoformat(),
                'status': 'completed',
            }).execute()

    t_audit = PythonOperator(
        task_id='audit_log',
        python_callable=audit_log,
    )

    # DAG Topology
    t_ingest >> extract_tg >> t_validate >> t_gate >> t_update >> t_test >> t_audit

Error Handling & Alerts

Cenário Ação Alerta Escalação
Falha em ingestão (API down) Retry 2x, depois fail Slack: #manta-alerts DevOps (30 min)
Contradição entre agentes Pausa DAG Slack: #manta-ops mencionando @mneves MN (imediato)
Gate crítico (lei/norma) Pausa. Aguarda `/kb-approve` Slack com diff de mudanças MN (até 24h timeout)
Falha em testes de modelo Rollback automático para versão anterior Slack: #manta-alerts, tag @mneves Alertar que drift detectado
Timeout em validação (>30 min) Kill task, rollback Slack DevOps + MN

}

Trace Completo

Auditoria imutável em kb_audit:

project_id → insights → validation → gate_decision → kb_update → test_result → publish → audit_id

Cada etapa tem timestamp + responsável (system ou MN) + assinatura digital.

Security & Approval Gates

Threshold para Auto-Update

Tipo de Mudança Confiança Mínima Gate Humano?
Feature normativa (ex: "nova norma ANEEL") 0.90+ Sim, sempre
Risk/benchmark atualizado 0.85+ Não (auto)
Typo/correção menor 0.75+ Não (auto)
Contradição detectada N/A Sim, escalação

Assinatura Digital

Toda mudança crítica é assinada com chave privada (armazenada em AWS Secrets Manager):

def sign_change(change_dict, secret_key):
    import hmac, hashlib
    payload = json.dumps(change_dict, sort_keys=True)
    signature = hmac.new(
        secret_key.encode(),
        payload.encode(),
        hashlib.sha256
    ).hexdigest()
    return {
        'change': change_dict,
        'signature': signature,
        'timestamp': datetime.now().isoformat(),
    }

RBAC para Approvals

  • Viewer: Pode ler logs/status via `/kb-status`
  • Approver: Pode executar `/kb-approve` (only MN)
  • Admin: Pode fazer `/kb-rollback` (only DevOps lead)
